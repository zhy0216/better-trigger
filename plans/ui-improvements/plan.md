# Dashboard UI 改进

## 意图

用户在了解并打开项目自带 Dashboard 后，调用 `$auto-dev UI 改进`，随后补充“UI 改进下”。本轮是现有前端的视觉与交互打磨：让运行信息更容易扫描、排查步骤更顺畅，并使窄屏也能完成核心操作。保留 Better Trigger 当前深色默认、紫色强调、亮色主题和开发者工具定位。已询问可选侧重点；截至写入没有进一步偏好，采用综合打磨的默认方案，不以此阻塞执行。

按 auto-dev 流程，本阶段只提交本目录内的计划和任务队列，随后通过 Herdr 在新 session 启动实现，不在规划 session 修改业务代码。协调器使用 OpenCode auto + `bailian-token-plan/qwen3.8-flash`；任务 difficulty 按执行技能映射：easy/medium → flash，hard → max。其他既有计划中针对其他任务的模型要求不复制到本计划。

## 目标与范围

### 目标

- 统一页面标题、指标、次要文字、间距、按钮、状态与设置面板的视觉层级；默认主题有清楚可读的文字和边界。
- Runs、Tasks、Schedules、运行详情在 390、768、1440px 宽度下均能完成核心浏览和操作，375px 作为额外边界复核。
- 用明确的空态、筛选恢复、暂停状态、日志跟随状态减少理解成本。
- 保留并验证键盘操作、焦点恢复、分页、环境隔离、连接与认证错误反馈。
- 完成后交付当前源码的本地预览地址和浏览器验证证据，不能把旧容器页面当成新 UI。

### 非目标

- 不实现 Alerts / Deployments 后端，也不让占位项看起来像可用功能；保留其既有深链接。
- 不修改 API 契约、数据库、SDK、任务运行逻辑、认证策略或重试幂等协议。
- 不引入 UI 框架、路由框架、图表库、远程字体、图片生成或新运行时依赖；现有 SVG 图标和 CSS 足够。
- 不做全站中文化、不重新设计品牌、不加入示例统计伪装真实数据；产品界面继续使用现有英文。
- 不增加设置持久化、全局命令面板、任意全文搜索、真实告警或发布管理；不进入本轮队列。
- 不发布远程站点、不推送 Git、不清空或重建用户现有数据库/容器卷。

## 方案

### 1. 共享视觉与响应式 Shell

- 保留现有灰阶与紫色强调，用背景、边界、文字权重、适当留白区分全局导航、页面标题、内容与辅助信息，避免把每个字段都做成抢眼卡片。
- 所有必要文字（指标标签、状态、辅助操作）用可读的 token；普通文字对比度以至少 4.5:1、控件/焦点边界 3:1 为验收目标，测量实际背景合成后的颜色。不能只提高 opacity 后宣称达标。
- 以 768px/1100px 为初始断点；按真实内容调整具体阈值。桌面保留展开/折叠侧栏，小屏使用可关闭的导航抽屉；隐藏导航不得保留可聚焦元素。按钮具有 accessible name、展开状态、aria-controls，当前路由标识 aria-current。
- 导航抽屉支持 Escape/遮罩关闭，关闭后恢复触发焦点，路由选择后关闭；模态抽屉开启时管理焦点且背景不可交互，宽度变化不能遗留焦点锁或遮罩。
- 顶栏控件重排，环境选择、主题、设置和连接状态可达；可以收起重复文字但必须保留 accessible name。Page 及运行详情主区域使用一致的 main landmark；避免嵌套多个 main。
- 用 `100dvh` 加合适 fallback 处理动态浏览器高度；focus-visible 清楚，尊重 prefers-reduced-motion，关闭动画时状态仍清晰。
- Tweaks 改为同主题的 Display settings 呈现；沿用现有 React 状态和控件功能，不新增存储。面板限制在视口内，允许键盘关闭并恢复设置按钮焦点；保留拖动监听清理测试，拖动不是访问内容的前提。
- 将影响布局的内联样式迁到明确的组件类。共享 CSS 由任务 01 管理；并行页面任务新增并 import 自己独立的样式文件，避免同时修改全局文件。

### 2. Runs 的浏览与筛选

- 桌面保留对齐的运行列表；窄屏每条运行重排为状态/任务为主、run ID/耗时/触发方式/版本/时间为辅，信息可读且行仍有唯一、可键盘操作的打开入口。
- 状态筛选组可换行或局部滚动，搜索栏有明确标签，所有状态完整可达。继续把 taskId 交给服务端，不扩大其匹配语义，也不加会产生假空态的客户端过滤。
- 区分未产生运行与筛选无结果；筛选无结果提供一次清除 status + taskId 的操作，保留当前环境和 live 状态。
- 可显示“已加载 N 条”及 Live/Paused 状态，但不能冒充服务端总量或全局状态计数。分页错误和重试入口必须保留。

### 3. Tasks 与 Schedules

- Tasks 指标窄屏两列、极窄时一列，卡片小屏单列、宽屏两列。突出任务身份、24h 运行量与成功率，延迟/路径作为次要信息；零、未知、不可用分别呈现，禁止用 0 掩盖 API 错误。
- 保留 workers/schedules 不可用提示及正确统计来源；对长 task ID / file path 做换行或可查看全文的截断。
- Schedules 宽屏保持扫描效率，窄屏让任务/cron/时区/next/last/开关分行；暂停显式显示 Paused，避免降低整行文字对比度。依然用具名 switch、pending 禁用及既有回滚/错误反馈。

### 4. Run 详情排查

- 桌面保留瀑布图 + Inspector；小屏采用 Trace / Details 的可访问切换或自然纵排，不能仅把 Inspector 藏起来。复用同一份选择状态和数据，切换尺寸/面板不能重置 selected span 或重新发起重复轮询。
- 时间轴保留最小可读宽度并在自己的容器横向滚动，标签宽度随断点变化；页面本身不得横向溢出。日志和代码块只在必要时局部滚动。
- 日志显示 Following/Paused 及 Jump to latest；手动向上阅读时新日志不抢位置；加载更早日志后保持可见锚点；选择 span 范围按钮标明当前范围并暴露 aria-pressed。
- 日志空态分别说明：尚在运行等待日志、终态无日志、当前 span 范围无日志。现有 hasOlderLogs/loading/error 不被局部过滤吞掉。
- 失败 span 先展示错误摘要，再展示大 Payload；Error/Payload/Output 可展开并复制完整原值。复制成功/失败通过可访问状态反馈；权限拒绝不能假报成功。切换 span 不残留旧内容或反馈。
- child run ID 可显示/复制全文；本轮不新增未经 API 验证的跳转。保留所有取消/重试状态限制、pending guard、幂等 key 与重试后打开新 run 的行为。

## 拆解与文件边界

一个 todo 对应一个独立 worktree、一个最终 commit。优先级均为 P1（核心可用性），最终验收为 P2；难度按状态/焦点/滚动回归的实际复杂度判断。

| 01 | `01-responsive-shell.md` | hard / max | 无 | App、Shell、Layout、TweaksPanel、navigation、全局主题与共用 primitives；相关 shell/主题测试 |

## 校验与交付

每个任务至少运行 web typecheck/lint 和与行为变更直接相关的既有测试；交互变更补充能捕获真实回归的测试，纯样式靠浏览器验证。

合并后的整体验证：

```bash
bun run typecheck
bun run lint
bun run build
bun run test
```

遵循 `agent.md` 使用 Bun。不要通过 `bun run --bun test` 强制改变测试解释器；如果整仓测试需要 PostgreSQL，按当前隔离测试约定创建独立测试资源，不能使用用户运行中的业务库。记录跳过项/环境缺失和真实失败，不能把未运行当作通过。

浏览器矩阵：

- 390×844、768×1024、1440×960；额外 375px 宽和 200% 缩放边界；深色/亮色、comfortable/compact。
- Runs：有记录/首次空态/筛选无匹配/加载更多失败；状态和 taskId 联合筛选/清除；live 暂停恢复；详情返回和浏览器前进后退。
- Tasks / Schedules：正常/长名称/空数据/次要数据不可用；开关成功/失败回滚/pending；环境切换无旧数据闪回。
- Run：多层 span、长 payload、失败 stack、无日志、历史分页及分页错误；滚动暂停/跳到最新；复制成功/失败；取消和重试行为可用，模拟写操作用明确的测试数据。
- Shell：键盘全流程；小屏导航和设置可开闭，Escape 与焦点恢复；200% 缩放不遮住关键控制；无页面级水平溢出；允许时间轴和大代码块内部滚动。
- 真实渲染后检查无新增 console error；保存主要页面桌面与移动截图，证据明确区分 live API 和受控测试 fixture。fixture 只能用于隔离验证，不写进产品数据路径。

完成后提供从本次合并源码启动的本地 UI。优先用 Vite 开发预览连接本地 daemon，绑定 loopback 并报告实际端口；daemon 不运行时可按根 README 启动本地 Compose（沿用先前用户的本地启动授权），保留数据卷，检查端口冲突。若使用嵌入 UI 的容器，先构建包含本次改动的镜像并验证入口资源；不能只刷新旧镜像后声称 UI 已更新。不要为了视觉检查触发真实用户业务任务。

## 风险与假设

- 用户没有提出品牌重做、特定参考网站或语言切换；默认保持现有方向。后续偏好到达时协调器更新范围。
- 内联样式与 CSS 混用可能让断点失效；实际浏览器布局是验收依据，JSDOM 通过不代表响应式布局正确。
- 模态抽屉、设置浮层的 Escape/焦点/层级需要协同；01 一并拥有相关文件，减少并行冲突。
- 日志分页 + 滚动跟随 + span 切换涉及现有细致行为，所以 05 定为 hard，复用既有数据流并做行为回归。
- 现有测试中有对固定视觉实现的断言（如 Schedules opacity）；改为验证用户可观察状态与回滚，不删除回归保障。
- 当前本地容器状态可能由用户改变；最终预览必须重新检查，并如实报告地址及后端状态。
